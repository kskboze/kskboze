# ⛳ ゴルフ場 営業指示エージェント

8コースのゴルフ場を束ねる営業統括本部のための、**毎朝の営業指示を自動で作るシステム**です。

過去の来場実績・お客様の来場周期・先々の予約状況・月次予算を組み合わせて、

> 「**霞ヶ浦カントリークラブ**の、**来場サイクルが来た42名**に、**LINE**で、**この文面**を送ってください」

という、そのまま実行できる形の指示を毎日出します。

## このシステムができること

| やりたいこと | このシステムの答え |
|---|---|
| 過去の実績から傾向を掴みたい | 来場実績からお客様ごとの**来場周期・平均単価・利用曜日**を算出します |
| 来場履歴でお客様を分類したい | 通算来場回数で **F1〜F5** に、来場間隔で **順調／離反予備軍／休眠／離脱** に自動分類します |
| 先々の予約から弱日・強日を知りたい | 例年の同じ時期・同じ曜日と比べた**予約の入り具合**で、各日を **S〜D** の5段階に判定します |
| 予算達成に向けた施策がほしい | 着地予測と予算の差を**「あと何人必要か」**まで落とし込み、埋めるための指示を出します |
| 予約周期に合わせて案内したい | **「次回来場の予測日 − 予約リードタイム」** が今日にあたる方を毎朝自動で抽出します |
| リピーターを増やしたい | 1回のみの方、2回の方、3〜5回の方に**それぞれ別の施策**を指示します |
| 月初に達成予測100%にしたい | 前月のうちに**翌月の不足分**を算出し、先行予約で埋める指示を出します |

### 具体例：出てくる指示

```
[最優先] 湘南シーサイドゴルフ｜2026-10の予算に489名不足（予測86.4%）
  手段: メール   対象: 283名   見込み: 54名 / 97万円   期限: 2026-09-30

  理由: 2026-10の着地予測は予算の86.4%、不足額は8,816,129円（約489名分）です。
        来月に入ってから動くと直前値引きになり単価が崩れます。
        今月のうちに前受けで埋めておけば、通常単価のまま達成できます。

  行動: 来月の空きが目立つ日（10/30(金)、10/26(月)…）を提示し、
        今月中のご予約で特典が付く形で先行予約を獲得してください。
```

## はじめかた（3ステップ）

### 必要なもの

* Python 3.10 以上
  * Windowsの方は [python.org](https://www.python.org/downloads/) からインストールしてください。
    インストール画面の下にある「**Add Python to PATH**」に**必ずチェック**を入れてください。
    （これを忘れると、後の手順で「python は認識されていません」というエラーになります）

---

### ステップ1：プログラムをパソコンに用意する

まず、このプログラム一式をご自分のパソコンにダウンロードします。

#### 方法A：ZIPファイルでダウンロードする（おすすめ・Gitが不要）

1. ブラウザで次のアドレスを開くと、ZIPファイルのダウンロードが始まります。

   ```
   https://github.com/kskboze/kskboze/archive/refs/heads/claude/keen-gates-nkrkmp.zip
   ```

2. ダウンロードしたZIPファイルを**右クリック →「すべて展開」**で解凍します。
3. 解凍してできた `kskboze-claude-keen-gates-nkrkmp` フォルダを、
   デスクトップなど分かりやすい場所に置いてください。
4. その中の **`golf-sales-agent`** フォルダが、このプログラム本体です。

#### 方法B：Gitでダウンロードする

Gitをお使いの場合は、PowerShell（Windows）またはターミナル（Mac）で次を実行します。

```bash
cd ~
git clone -b claude/keen-gates-nkrkmp https://github.com/kskboze/kskboze.git
cd kskboze/golf-sales-agent
```

---

### ステップ2：サンプルデータで動きを見る

実データの準備には時間がかかりますので、**まずは架空のデータで全機能を体験する**ことを
強くおすすめします。8コース・約5万名・約10万件の実績が自動で作られます。

**Windows の方**

`golf-sales-agent` フォルダの中にある **`setup_sample.bat`** をダブルクリックしてください。

**Mac / Linux の方**

```bash
cd golf-sales-agent
python3 scripts/generate_sample_data.py
python3 -m app.cli run
```

---

### ステップ3：起動する

**Windows の方**

同じフォルダの **`start.bat`** をダブルクリックしてください。

**Mac / Linux の方**

```bash
./start.sh
```

黒い画面（コマンドプロンプト／ターミナル）が開いたら、そのまま閉じずに、
ブラウザで **http://127.0.0.1:8000** を開いてください。

> 終了するときは、黒い画面で `Ctrl` + `C` を押してください。

### 実データに入れ替えるとき

サンプルで動きを確認したら、`data/golf.db` というファイルを削除してください。
その後アプリを起動し、画面の「**データ取込**」からご自分のCSVを取り込みます。

## 画面の使い方

### ダッシュボード（全体像）

* 今月・来月の**全社の予算達成予測**
* コース別の達成率と**不足人数**
* 本日の重要指示（上位8件）
* 顧客ランクの構成

毎朝ここを開き、赤くなっているコースから対処していく、という使い方を想定しています。

### 本日の指示

* 優先度順（最優先 → 今週中 → 計画的 → 余力があれば）に並びます
* ゴルフ場・優先度・施策で絞り込めます
* カードをクリックすると詳細画面へ

### 指示の詳細

1. **なぜこの指示が出ているのか** … 根拠となる数字が書かれています
2. **具体的にやること** … 現場への指示文です
3. **お送りする文面** … コピーして配信ツールに貼り付けられます
4. **対象のお客様** … 「対象者リストをCSVで保存」で全員分をダウンロードできます
5. **完了にする** … 押すと接触履歴が残り、そのお客様はしばらく他の指示の対象になりません

> 💡 **「完了にする」は必ず押してください。** これが送りすぎ防止の要になります。

### コース詳細

* 今月の売上の内訳（確定実績＋現在の予約＋今後の見込み）
* **需要カレンダー**（弱日・強日が色で一目で分かります）
* 予約経路の構成（ポータル比率の確認に）

### 顧客分析

* ランク別のリピーター動向
* 来場周期の分布
* 今後2週間の**アプローチ予定人数**
* お客様の検索

### 設定

判定のしきい値を調整できます。最初は初期値のままで運用し、実績が溜まってから調整してください。

## データの取り込み方

画面の「データ取込」から、CSV または Excel をアップロードします。

### 取り込む順番

1. **コースマスタ** … 8コース分（コースID・コース名・定員）
2. **顧客マスタ** … お名前・連絡先・**配信許諾**
3. **来場実績** … 過去1年以上あると精度が上がります
4. **予約データ** … 今日以降の予約
5. **月次予算** … 今月・来月分

> 来場実績と予約データだけでも動きます（コースと顧客は自動で作られます）。
> ただし連絡先が無いお客様には案内を送れないため、顧客マスタも必ず入れてください。

### 列名は自動で判別します

CSVの見出しは予約システムごとにバラバラですが、次のような表記ゆれは自動で吸収します。

| システム内部の項目 | 読み取れる見出しの例 |
|---|---|
| 来場日 | 来場日 / プレー日 / 利用日 / play_date / date |
| 顧客ID | 顧客ID / 会員番号 / 顧客番号 / customer_id |
| 売上 | 売上 / 売上金額 / 利用金額 / 金額 / revenue |
| 予約経路 | 予約経路 / 販売経路 / チャネル / 媒体 / channel |

全角・半角、スペース、括弧の違いは無視されます。
対応できない見出しがあった場合は、取り込み後の画面に「使わなかった列」として表示されますので、
`app/importer.py` の `COLUMN_ALIASES` に追記してください。

### その他の仕様

* **文字コード**：Shift_JIS（Excelの標準）でも UTF-8 でもそのまま読めます
* **日付**：`2026/10/3`・`2026年10月3日`・`20261003` などを自動で統一します
* **金額**：`12,300円` のような表記から数字だけを取り出します
* **許諾**：`○`・`可`・`1` は許諾あり、`×`・`不可`・`0` は許諾なしとして扱います
* **重複**：同じファイルを2回取り込んでも、IDが同じ行は上書きされるだけなので重複しません

## どんな指示が出るのか（施策ルール一覧）

| ID | 施策 | 優先度 | 対象 | ねらい |
|---|---|:--:|---|---|
| R51 | 当月予算のラストスパート | 最優先 | 運営指示 | 残り日数から1日あたりの必要人数を逆算 |
| R50 | **翌月予算の先行対策** | 最優先 | F3〜F5の順調な方 | 月初に達成予測100%にしておく |
| R31 | 緊急送客（直近の最弱日） | 最優先 | 2回以上・連絡可 | 14日以内の空き枠を売上ゼロにしない |
| R01 | **予約周期アプローチ** | 最優先 | 周期が実測できた方 | 検討中のタイミングにピンポイントで届ける |
| R02 | 常連の離反防止 | 最優先 | F4・F5の離反予備軍 | 常連1名の離反は年間数十万円の損失 |
| R30 | 弱日への送客 | 今週中 | その曜日によく来る方 | 値引きに頼らず弱日を埋める |
| R10 | **初回のみ → 2回目** | 今週中 | 通算1回・150日以内 | リピーター減少への最大の打ち手 |
| R11 | **2回目 → 3回目** | 今週中 | 通算2回・180日以内 | 「3回の壁」を越えると定着する |
| R40 | 強日の単価アップ | 今週中 | 運営指示 | 埋まる日に安いプランを残さない |
| R12 | 育成層の常連化 | 計画的 | F3で順調な方 | 回数券・年間優待で頻度と単価を同時に上げる |
| R20 | 休眠復活 | 計画的 | 休眠・2回以上 | 「変わった点」を伝えて呼び戻す |
| R60 | ロイヤル顧客の維持 | 余力があれば | F5で順調な方 | 販売ではなく感謝の接点を作る |

### 送りすぎを防ぐしくみ

同じお客様が複数の施策に当てはまることは頻繁にあります。そこで、

1. **1日1人1通まで** … 同じ方が複数の指示に重複しないよう自動で整理します
2. **個別施策を優先** … 一斉配信より、お電話などの個別対応を先に割り当てます
   （一斉メールが常連様を先取りしてしまうのを防ぎます）
3. **14日間のクールダウン** … 「完了」にした指示の対象者は、14日間は次の対象になりません
4. **必要人数の6倍まで** … 100名分の空きを埋めるために8,000名へ一斉送信することはしません

## 計算の考え方

### 1. 来場周期とアプローチ推奨日

```
来場周期     = 来場間隔の中央値
                （平均ではなく中央値。たまたま長く空いた1回に引きずられないため）
リードタイム = 予約日からプレー日までの日数の中央値
次回来場予測 = 最終来場日 ＋ 来場周期
案内推奨日   = 次回来場予測 − リードタイム   ★ここが指示のタイミング
```

**例）来場周期30日・予約は14日前に入れる方**
前回来場が10月1日なら、次回は10月31日ごろ。予約は14日前なので、**10月17日にご案内**します。

### 2. 顧客の分類

| ランク | 通算来場回数 | | 状態 | 判定 |
|---|---|---|---|---|
| F1 | 1回 | | 順調 | 周期の1.2倍以内 |
| F2 | 2回 | | 離反予備軍 | 周期の2.0倍以内 |
| F3 | 3〜5回 | | 休眠 | それ以上 |
| F4 | 6〜11回 | | 離脱 | 540日超 |
| F5 | 12回以上 | | | |

同じ「90日ぶり」でも、周期30日の方なら異常、周期180日の方なら正常です。
**その方にとっての普通** を基準にすることで、無駄な案内を減らしています。

### 3. 弱日・強日の判定（ペース比較）

単に「予約が少ない日＝弱日」では判断を誤ります。2ヶ月先はどこも少ないからです。

```
ペース比 = 今の予約充足率 ÷ 例年の同じ時期・同じ曜日の「同じ◯日前」の充足率
```

| 判定 | 条件 | 打ち手 |
|---|---|---|
| **S** 強日 | ペース比 1.10以上、または充足率85%以上 | 値引き停止・上位プランへ |
| **A** やや強 | ペース比 1.00以上 | 通常運営 |
| **B** 標準 | ペース比 0.90以上 | 通常運営 |
| **C** 弱日 | ペース比 0.90未満 | 既存顧客へ送客 |
| **D** 最弱日 | ペース比 0.75未満 | 緊急送客・在庫開放 |

### 4. 予算の着地予測

```
着地予測 = ①確定実績 ＋ ②現在の予約 ＋ ③これから入る見込み
必要人数 = （予算 − 着地予測） ÷ 平均単価
```

③は「例年ならこの時期からこれだけ積み上がる」という実績から算出します。

### 5. 見込み売上の試算

```
見込み来場人数 = 対象人数 × 想定反応率 × 1組あたり3.2名
```

想定反応率は施策ごとに設定されています（周期アプローチ15%、初回→2回目4%、休眠復活2%など）。
**全員が来てくださる前提の数字は出しません。** 実績が溜まったら `app/engine/rules.py` の
`RESPONSE_RATES` を実測値に置き換えてください。

## AI（Claude）で文面を作る

APIキーが未設定でも**システムは完全に動作します**（あらかじめ用意した36種類の文面が使われます）。

AIを有効にすると、施策の背景を踏まえた、より自然な案内文が毎回作られます。

```bash
cp .env.example .env
```

`.env` を開いて、[Anthropic Console](https://console.anthropic.com/) で取得したキーを記入します。

```
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxx
AI_MODEL=claude-sonnet-5
```

```bash
pip install anthropic
```

アプリを再起動すると有効になります。設定画面で状態を確認できます。

> **設計上の考え方**
> 「誰が対象か」「何人必要か」といった数字の計算は、すべてプログラム側で確定させています。
> AIには**文章表現だけ**を任せています。こうすることで、
> ・毎日同じ条件なら同じ対象者が出る（結果がぶれない）
> ・AIが数字を作り話すことがない
> という、業務で使ううえで大切な安定性が保てます。
> 通信エラーやAPI残高切れの場合も、自動でテンプレート文面に切り替わるため、業務は止まりません。

## 困ったときは

| 症状 | 対処 |
|---|---|
| `python3: command not found` | Pythonが未インストールです。python.org からインストールしてください。Windowsでは `python3` ではなく `python` の場合があります |
| `cd : パス ... が存在しないため検出できません` | プログラムのダウンロードがまだです。[はじめかた](#はじめかた3ステップ)のステップ1をご覧ください |
| `start.sh` が実行できない（Windows） | Windowsでは `start.bat` をお使いください |
| `ModuleNotFoundError: No module named 'fastapi'` | `pip install -r requirements.txt` を実行してください |
| ブラウザで開けない | アプリを起動したターミナルを閉じていませんか。`./start.sh` をもう一度実行してください |
| ポート8000が使用中 | `python3 -m uvicorn app.main:app --port 8001` のように番号を変えてください |
| CSVが文字化けする | 出力時の文字コードを Shift_JIS か UTF-8 にしてください（どちらも読めます） |
| 指示が0件になる | 来場実績と予約データが入っているか、「データ取込」画面でご確認ください |
| 弱日がまったく出ない | 過去の来場実績に**予約日（booked_at）**が入っているかご確認ください。ペース比較にはこの列が必要です |
| データを最初からやり直したい | `data/golf.db` を削除して、もう一度取り込んでください |

### 処理の流れ

```
CSV取込 → ①顧客分析 → ②需要分析 → ③予算予測 → ④ルール実行 → ⑤重複整理 → ⑥文面作成 → 画面表示
          (周期・ランク)  (弱日・強日)  (着地予測)   (12ルール)    (送りすぎ防止)  (テンプレ/AI)
```

## 今後の拡張について

このシステムは**指示と対象者リストの出力まで**を担当します。実際の配信は、現在お使いの
配信ツールにCSVを取り込んで行ってください。

将来、配信までを自動化する場合は、`app/engine/` に配信サービス（SendGrid、LINE公式アカウント、
SMS配信サービスなど）との連携を追加する形になります。その際も、施策の判断ロジックは
そのままお使いいただけます。

また、運用して実際の反応率が分かってきたら、`app/engine/rules.py` の `RESPONSE_RATES` を
実測値へ置き換えてください。見込み売上の精度が大きく上がります。
